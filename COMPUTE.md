# Три вычислительные площадки

Проверено 14.11.2026. Ключи лежат вне git: `participant-04/` и `japanfold-*.txt` в `.gitignore`.

## Главное: площадки дополняют друг друга

| | Apheris VM | Nebius Scientific AI | JapanFold |
|---|---|---|---|
| Что | H100 80GB, только наша команда | около 60 моделей на хостинге, GPU не нужен | хостинг моделей |
| Делится с кем | только мы (но один GPU на 5 человек) | 16 команд на платформе | неизвестно |
| Доступ | ssh по ключу `team-3` | API-ключ, работает | **код надо активировать вручную** |
| Бюджет | нет лимита | кредиты на аккаунте | 1000 USD, код одноразовый, не истекает |
| Козырь | **чекпойнты RFD4 под HER2 и под антитела** | AntiFold, NanoBodyBuilder2, Protenix v2, StaB-ddG без установки | ещё один пул мощностей |

**Ключевое различие.** RFD4-Proteina на Nebius это общая модель: в их же рецептах написано,
что выход это *general protein binder, not a VHH*, антительного приора у неё нет. Антительные
и HER2-специфичные чекпойнты есть **только на нашей VM от Apheris**. Это наш эксклюзив,
которого у большинства команд в таком виде нет.

Отсюда разделение труда:
- **VM**: генерация дизайнов на чекпойнтах `her2-*` и `antibody-*`, плюс `refold-prepare`
  и `refold-score`. Это то, что умеет только она.
- **Nebius**: всё остальное, чтобы не занимать единственный H100. AntiFold для редизайна CDR,
  NanoBodyBuilder2 для структуры нанотела, Boltz2 и OpenFold3 для кофолдинга, MSA-поиск,
  StaB-ddG для ddG связывания.

## Nebius: как пользоваться

Установка уже сделана, скиллы лежат в `~/.claude/skills/`. Контрольная сумма пакета сверена.
Установщик ключи не читает и MCP не регистрирует, проверено чтением.

```bash
cd participant-04
export NEBIUS_CREDS="$PWD/credentials.private.json"
F=~/.claude/skills/nebius-scientific-ai/forge.py
python3 "$F" models          # 34 из 59 моделей с проверенным форматом входа
python3 "$F" schema <model>  # читать ПЕРЕД тем как подбирать аргументы
python3 "$F" runs            # все наши запуски
python3 "$F" status op-xxxx
python3 "$F" wait op-xxxx
python3 "$F" fetch op-xxxx --dest results/<имя>
python3 "$F" resume op-xxxx  # после сбоя приватного хранилища
```

Проверено end-to-end: NanoBodyBuilder2 на каркасе 3EAK, 115 секунд от отправки до успеха,
скачались PDB с уточнением в OpenMM 8.6.1, FASTA и метрики. Запуск `op-448814a89adff81b`.

**Никогда не запрашивать полный каталог моделей**: ответ около 930 КБ и забивает контекст.

## Модели на Nebius, которые нам нужны

| Модель | Время | Зачем |
|---|---|---|
| `antifold` | ~110 с | **редизайн CDR нанотела**, Spearman с аффинностью 0.418 против 0.264 у ESM-2 |
| `nanobodybuilder2` | ~2 мин | структура VHH, точнее общих фолдеров |
| `abodybuilder3` | ~2 мин | то же для парного антитела, заголовки H и L |
| `boltz2` | ~80 с | кофолдинг пары, **нужен A3M на каждую цепь** |
| `openfold3` | ~3 мин | второе мнение, плюс условие денежного приза |
| `protenix-v2` | ~20 мин | лучший на антителах по бенчмаркам, но долгая очередь |
| `proteinmpnn` | ~100 с | последовательность под готовый бэкбон |
| `esm-if1` | ~4 мин | inverse folding, тот же tar, `custom_chain_mode` |
| `msa-search-pdb70` | ~40 с | выравнивание для Boltz2 и OpenFold3 |
| **`stab-ddg`** | ~12 мин | **ddG связывания для точечных мутаций между двумя цепями** |
| `esm2-650m`, `esm2-3b` | 4-8 мин | скоры последовательностей |
| `igbert` | ~4 мин | эмбеддинги тяжёлой и лёгкой цепи |
| `rfd4-proteina` | ~5 мин | общий связыватель, **без антительного приора** |
| `mosaic` | ~22 мин | дизайн связывателя по FASTA мишени, медленно |

`openfold2` не работает: эндпойнт не поднимается, падал и под нагрузкой, и на пустой
очереди. Не планировать.

`stab-ddg` стоит отдельного внимания: это единственный доступный предиктор именно ddG
связывания между двумя партнёрами, то есть ровно то, чего нам не хватало для ранжирования.
Проверить его калибровку на известных мутациях до того, как доверять.

## Грабли Nebius, названные самими организаторами

1. **Запуск выглядит зависшим.** Он в очереди, а не сломан. Первый вызов может ждать
   15 минут, потому что модель загружается. Шестнадцать команд делят платформу,
   поэтому долгие задачи ставить заранее.
2. **`private storage is temporarily unavailable`** это сбой платформы, лечится
   `forge.py resume op-xxxx`, подхватывает тот же запуск.
3. **Модель отвергает вход.** Читать `forge.py schema <model>`, не подбирать формы наугад.
4. **`missing required fields: request`** у молекулярной динамики: добавить `--wrap-request`,
   нужно всем пяти движкам.
5. **Один запуск не отправлять дважды**, иначе ждать придётся два раза.
6. У Boltz2 на Nebius **в выводе нет ipTM**. Их рецепт прямо говорит не сообщать его.
   Для числа по интерфейсу считать контакты между цепями в выданном mmCIF самостоятельно.
7. Bundle молекулярной динамики подавать **гзипованным как есть**, распакованный движок
   отвергает.

## Формат входа Boltz2

Нужно выравнивание на каждую цепь. Однострочное годится для первого взгляда.

```json
{"polymers": [
  {"id": "A", "molecule_type": "protein", "sequence": "<VHH>",
   "msa": {"msa_search": {"a3m": {"alignment": ">query\n<VHH>\n"}}}},
  {"id": "B", "molecule_type": "protein", "sequence": "<TARGET>",
   "msa": {"msa_search": {"a3m": {"alignment": ">query\n<TARGET>\n"}}}}]}
```

Ориентир из их прогона: одиночный VHH даёт confidence 0.93, реальная пара 1ZVY даёт
confidence 0.77 и pTM 0.57. То есть **падение confidence при переходе к паре это норма**,
а не признак плохого дизайна.

## AntiFold: редизайн CDR

```bash
COPYFILE_DISABLE=1 tar -cf nebius-runs/inputs/antifold.tar -C nebius-runs/inputs 1zvy.pdb
python3 "$F" submit antifold \
  --entry 'workload|inverse-folding-tar/v1|nebius-runs/inputs/antifold.tar' \
  --params '{"pdb_file":"1zvy.pdb","nanobody_chain":"A","nanobody_mode":true,
             "regions":"CDR1 CDR2 CDR3","num_seq_per_target":5,"sampling_temp":"0.20"}' \
  --label antifold-1
```

Возвращает FASTA с новыми последовательностями и скорами, плюс CSV с перплексией по
остаткам и предполагаемой областью каждой позиции. Дальше каждую последовательность
кофолдить с мишенью.

`COPYFILE_DISABLE=1` обязателен на macOS, иначе tar тащит метаданные `._*`.

## Что в репозиторий коммитить можно

Папки `results/` и `nebius-runs/` держат выходы и id запусков, ключей в них нет.
Их стоит коммитить: жюри требует показать, откуда взят каждый балл, а id запуска это
и есть происхождение числа.

## JapanFold: нужно действие от человека

Код на 1000 USD компьюта, один на команду, срабатывает один раз и не истекает, то есть
кредит остаётся и после хакатона.

Активация: `japanfold.aiand.com`, кнопка Sign in, вход по email без карты, затем ввести код.

**Это я сделать не могу**, нужен вход в аккаунт. Активируй сам, код в файле
`japanfold-oslo-hackathon-codes 3.txt`.

Ограничения публичного JapanFold из гайда участника (проверить, актуальны ли): 1024 остатка
на структуру, 10 структур на запуск, 10 связывателей на дизайн. Для большого антигена
обрезать до области эпитопа или идти через API. На JapanFold хостятся Boltz-2, OpenFold3,
RFdiffusion 3, BoltzGen, ESMC.
