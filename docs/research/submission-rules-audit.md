## Conflicts that need organizer interpretation

1. **Exactly 70% CDRH3 identity for optimisation.** The challenge deck uses `≤70%` (p. 6); the long guide uses `<70%` (pp. 2–3, 7). The PDFs disagree at exactly 70%. The supplied Slack summary does not resolve this boundary.
2. **Minimum distance from provided sequences for optimisation.** The challenge deck says `≥2` mutations from every sequence in the provided data (p. 6), and the long guide's prose on p. 2 says at least 2 mutations from any provided antibody. Its flow and hard-filter list instead say “more than 2” / “strictly more than 2” point mutations (pp. 3, 7). That changes the exact-2 case. Scope wording also varies between every data sequence and any provided antibody/data point. Treat the precise threshold and comparison set as unresolved. The de novo rule is separately stated as at least 2 CDRH3 mutations away from trastuzumab (pp. 2–3).
3. **Ranking in the exact Slack schema.** The PDF requires a ranked list, while the five organizer supplied columns contain no rank. The row-order rule is unstated. Clarify before final export; do not add a sixth column without organizer instruction.
4. **Optimisation reference format.** The PDFs say “same format as trastuzumab” but do not identify whether the assay reference construct is Fab/paired or scFv. The current rows are paired variable domains. Confirm that this matches the trastuzumab reference used for the format gate.
5. **ScFv length details.** The PDF clearly says combined VH+VL for paired formats. For scFv it calls the limit the whole chain, but the flow says linkers are stripped before checks. The exact length input to `abguard` is not described.

## Draft CSV comparison

Read only. `output/submission-draft/team-3-draft.csv` has the exact five supplied headers, 53 unique IDs, 10 rows marked optimisation and 43 marked de novo in `design_description`. Every row is `kind=paired` with both variable-domain fields populated. The CSV hash is `661bffcab9fb9e5c954d12e38e4424d3c1641550de82a68e7ce5ebf3340ecb87`.

The 53 rows exceed the PDF's maximum ranked list of 20, so this is correctly a research pool, not a final slot selection. The current filename is `team-3-draft.csv`; the README says `team-3` is the VM label and instructs replacing it with the confirmed team name. The draft has no explicit rank; its description labels intended track but that is not a rank.

The row sequences use canonical 20 amino acids. The local validation sidecar reports no odd cysteine counts and numbering confidence at least 0.1. Paired heavy-plus-light lengths range from 224 to 243 residues, below the combined 250 limit. The listed optimisation CDRH3 strings are 30–60% identical to `WGGDGFYAMD` by direct positionwise comparison. The current README also reports nearest provided-window edit distance 3 for each of the ten optimization picks, which clears both mutation thresholds under that local comparison. These are local checks, not official gate results. At the time of that preflight, the sidecar recorded `official_abguard_status=not_run_tool_unavailable` and `official_novelty_status=pending` for all rows. The README's tool search is scoped to inspected local/VM environments; it does not prove the internal service is unavailable or that any row passes the official database check.
